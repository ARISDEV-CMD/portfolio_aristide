ATELIER TECHNIQUE DE PRODUCTION #04

Créer une instance EC2 AWS et se connecter en SSH à distance

Le protocole opérationnel complet de l'ingénieur polytechnicien : du provisionnement de l'AMI Amazon Linux 2023 à l'analyse fine des Security Groups, jusqu'à la sécurisation cryptographique des clés privées RSA/ED25519 (.pem).

target Objectifs du Lab
  • • Déployer une instance EC2 dans le Free Tier (t2.micro / t3.micro).
  • • Maîtriser le filtrage strict des règles de Security Groups (Port 22).
  • • Établir un tunnel SSH sécurisé via CLI UNIX sans faille d'autorisation.
terminal Prérequis Système
  • • Compte AWS actif configuré avec région valide (ex. eu-west-3).
  • • Terminal UNIX fonctionnel (zsh, bash) ou PowerShell v7+.
  • • Suite OpenSSH native installée pour la négociation de clés.

SECTION 01 / ARCHITECTURE

Introduction & Cas d'usage en environnement d'entreprise

En tant qu'ingénieur, le provisionnement d'instances de calcul n'est pas un acte anodin. Dans l'écosystème AWS, Amazon Elastic Compute Cloud (Amazon EC2) fournit une capacité de calcul redimensionnable dans le cloud. Comprendre son cycle de vie est la fondation indispensable sur laquelle reposent les clusters Kubernetes, les runners CI/CD et les serveurs d'applications conteneurisées.

Pour des infrastructures soumises à de strictes réglementations industrielles, une instance mal configurée représente une passerelle de compromission directe. Cet atelier détaille la méthode appliquée à l'ENSPD garantissant isolation, traçabilité et conformité dès la première seconde d'exécution.

SECTION 02 / PROVISIONNEMENT

Choix de l'AMI & Dimensionnement optimisé

Privilégiez l'Amazon Linux 2023 AMI. Contrairement aux anciennes distributions CentOS ou Ubuntu non optimisées, AL2023 intègre par défaut le client AWS CLI v2, une stack OpenSSL 3 durcie et un noyau Linux 6.1 LTS configuré pour le virtualiseur AWS Nitro.

SECTION 03 / NETWORK SECURITY

Configuration réseau & Règles de Security Groups

Le Security Group agit comme un pare-feu d'état virtuel. Lors de l'initialisation de l'instance dans votre VPC public, l'erreur la plus commune consiste à autoriser le port 22 pour le CIDR global 0.0.0.0/0.

warning
Avertissement de Durcissement : Exposition SSH

N'ouvrez jamais le port 22 sur Internet libre (0.0.0.0/0). Les scanners Shodan et botnets analysent en continu les plages d'adresses IP publiques AWS. Sélectionnez systématiquement l'option "My IP" (Mon adresse IP) dans la console AWS pour restreindre l'entrée à votre routeur actuel.

SECTION 04 / PERMISSIONS CRYPTO

Gestion et durcissement des clés SSH (.pem)

Après le téléchargement du Key Pair généré par AWS (ex. polytech-lab-key.pem), le client SSH UNIX refusera d'utiliser cette clé si les permissions d'accès au fichier sont trop permissives (erreur classique UNPROTECTED PRIVATE KEY FILE!).

bash — terminal

# 1. Déplacer la clé dans le répertoire sécurisé SSH

mv ~/Downloads/polytech-lab-key.pem ~/.ssh/

# 2. Restreindre les permissions en lecture seule au propriétaire unique

chmod 400 ~/.ssh/polytech-lab-key.pem

SECTION 05 / EXÉCUTION

Connexion pas à pas depuis le terminal local

Récupérez l'Adresse IPv4 publique attribuée à votre instance EC2 dans le tableau de bord de la console de gestion AWS. Le compte par défaut configuré sur Amazon Linux 2023 est ec2-user.

terminal Session SSH Interactive

ssh -i ~/.ssh/polytech-lab-key.pem ec2-user@35.180.42.115
